- `inspect()` (src/lib/skill-source.ts) now returns the description a rejected folder's frontmatter parsed to, when it got past the YAML parse. Refusing to *connect* a folder was never a claim that it could not be *read*: on Ryan's machine 84 of 86 Global omissions are `name-mismatch` (the `gsd-*` skills declare `name: gsd:add-backlog` inside a hyphenated folder) with a perfectly good description. Nothing is reconstructed — `no-frontmatter`, `invalid-yaml` and `description-missing` stay null, which is exactly where a blank description is the honest report. `illegal-name` is rejected before the parse and deliberately stays bare rather than reordering a validation ladder that error-message tests pin.
- Library title / Skills tile: `n` is `skills.length` — the cards the grid draws (`index.ts` `const n=skills.length`, "title, tile and placeholder never count a card the grid does not draw"); `visibleSkillFolders` makes that coincide with the CLI's `counts.skillFolders` minus the folders the grid filters, so an older CLI needs no fallback. Since 2026-09-10 (W-07) the subtitle prints `plural(n,'skill')` (`"N skills"`, `"1 skill"`) instead of `"N skill folders in <root.label>"`; the root label is already the header title. Required because the bundled `/terum-skills` wrapper is now excluded from `countable()` — terum-skills listing its own placed component as a broken folder the user should fix was a defect — while the CLI still counts it as a folder on disk (`FRONTMATTER_PROBLEMS` in local-skills.ts). Folder counts and the sidebar badge therefore stay in agreement; only the grid is filtered.
- Version coupling (recorded, not fixed): `cliLocalRow` is `.strict()`, so an app that predates these fields cannot read a newer CLI's rows. The reverse skew is handled — every new field is `nullish`, so a newer app on an older CLI degrades to a dash and an empty description rather than failing the read (`index.test.ts`, "degrades to a dash when the CLI predates the character count"). The app and CLI ship together, so only a hand-mixed pair hits this.
