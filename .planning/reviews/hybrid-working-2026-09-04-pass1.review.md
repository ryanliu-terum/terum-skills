# ultrareview: working

Reviewed the working tree (mode `working`, base `HEAD`) of `/Users/ryanliu/Documents/Terum/terum-codex/m1-plumbing` — 38 files, +5566 lines. Four reviewer dimensions filed 139 raw findings; 55 were merged as duplicates before verification, and the remaining 84 went through 3-vote adversarial verification, leaving **30 confirmed**, 5 contested, and 44 unverified. The confirmed high-severity findings are not scattered: five of six sit on one seam — the credential and identity boundary between `login`, `team create/join`, `gitAuthEnv`, and the write guard. `login` will take any remote `normalizeRemote` can parse, prompt for a *GitHub* PAT, probe it against api.github.com, and store it as that team's token; `gitAuthEnv` then installs a bare `credential.helper` that answers for **every** host git talks to, so a GitHub PAT is offered as the HTTP password to gitlab.example. `hostOperationAllowed`/`isGitHubRemote` were written for exactly this scoping and have zero production callers. In parallel, `login` writes an unverified `teams.<t>.handle`, which is precisely the value `team join` treats as proof of ownership — turning the §5.4 collision check into a no-op and letting one user overwrite another's `people/<handle>.json` on `origin/main`. Two more independent data-loss paths round it out: `assertSafePath` checks only a lowercase *first* segment for `.git` while `applyTree` writes to disk *before* `guard()` runs (so `.Git/config` reaches the clone's live git config on a case-insensitive volume, and the cleanup then deletes it), and `terminalPrompter` never settles at EOF, so a non-TTY `team join` burns the GitHub invitation, leaves a partial clone, and exits **0**. The medium tier is dominated by tests that cannot fail: the prompter boundary lint is bypassable four ways that the test named "catches every way" does not probe, `normalizeAuthor` could be replaced with the identity function and the whole guard suite still passes, and the vitest env pins git config files but not `GIT_AUTHOR_*`/`GIT_DIR`, so fixtures can write into the developer's real repository.
