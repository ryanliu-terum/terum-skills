**Verdict.** This change set is a credential-hygiene hardening pass, and its core helper does not hold. `stripRemoteCredentials` fails on two shapes a user will hit on the first try: a password or email-style username containing `@` (the regex `[^@/]+@` stops at the *first* `@`, while git's `connect.c` uses `strrchr` and takes the *last* — so the tail of the token survives into git argv, the clone's `.git/config`, the persisted team config, and `io.print`), and a leading space (both regexes are `^`-anchored and `create()` at team.ts:53 passes `args.remote` untrimmed, so the whole token is echoed on the success path and in every error message). Both are one-line fixes in remote.ts that repair all call sites at once. The new tests cannot see either defect because every fixture is `https://me:ghp_leak@…` — exactly the one case the single-pass regex handles — so `not.toContain('ghp_leak')` is a vacuous pass. Two secondary issues: `assertOrigin` (teamRepo.ts:143) still interpolates a raw origin URL one function above the line this commit redacted, and `normalizeRemote`/`remoteToGitUrl` now hold two hand-synced copies of the same form cascade whose guards have already drifted (`https://host/.git` throws in one and is accepted by the other, contradicting the doc comment added at remote.ts:122). Two findings split the panel — the `CANONICAL_FORM` widening to single-label hosts, and whether silently dropping a user's credential is a defect or the intent — and need a human call.

## Terum invariants

- [ ] **[HIGH] `stripRemoteCredentials` stops at the FIRST `@`, so a credential containing `@` leaks into git argv, `.git/config`, and messages** — `/Users/ryanliu/Documents/Terum/terum-codex/m1-plumbing/src/lib/remote.ts:30` *(merges 2 reviewer reports across Terum invariants / Correctness & tests)*

  `const HTTP_USERINFO = /^((?:https?|git):\/\/)[^@/]+@/i;` (remote.ts:30) and `const SSH_USERINFO = /^(ssh:\/\/)([^@/:]*)(?::[^@/]*)?@/i;` (remote.ts:31). `[^@/]+` cannot cross an `@`, so the match ends at the first `@` — but git/curl take the **last** `@` in the authority as the userinfo separator. Verified against the shipped module:

  ```
  strip('https://me:gh@p_leak@git.example/team.git') -> 'https://p_leak@git.example/team.git'
  strip('https://user:p@ss@github.com/o/r.git')      -> 'https://ss@github.com/o/r.git'
  strip('ssh://git:p@ss@host/o/r.git')               -> 'ssh://git@ss@host/o/r.git'
  redact('https://me:gh@p_leak@git.example/...')     -> 'https://p_leak@git.example/...'
  strip('https://ryan@corp.com:ghp_TOKEN@gitlab.example.com/acme/team.git')
      -> 'https://corp.com:ghp_TOKEN@gitlab.example.com/acme/team.git'
  ```

  `URL_FORM`'s host group `([^/:]+)` accepts `@`, so it happily parses the leftover: `URL_FORM.exec('https://me:gh@p_leak@git.example/team.git')[1] === 'p_leak@git.example'`.

  Failure path — `terum-skills team create t --remote 'https://me:gh@p_leak@git.example/team.git'`: team.ts:53 keeps the half-stripped string as `remote`; remote.ts:133 hands that same string to `git ls-remote --heads -- <url>` and team.ts:265 to `git remote add origin -- <url>`, so the token tail lands in argv (visible in `ps`) and in the clone's `.git/config`; team.ts:81 `bindTeam` persists it; team.ts:84 prints `Created team ${name} at ${remote}`. On the join path `normalizeRemote` yields host `p_leak@git.example`, so `isGitHubRemote` returns false for a real github.com URL and a GitHub remote is silently pushed onto the generic-git branch.

  **Fix:** consume the whole userinfo the way git does — `/^((?:https?|git):\/\/)[^/]*@/` and `/^(ssh:\/\/)([^@/:]*)(?::[^/]*)?@/`, plus the same in `redact`'s first regex (remote.ts:48) — or loop the replace to a fixed point. Tighten `URL_FORM`'s host group from `([^/:]+)` to `([^/:@]+)` so a residual `user@` can never be parsed as host. Fixing the helper also fixes teamRepo.ts:246 and remote.ts:161, which rely on the same one-pass assumption. Add a password-with-`@` case to `src/lib/__tests__/remote.test.ts:48`.

- [ ] **[LOW] `remoteToGitUrl` silently deletes a user-supplied credential, turning a previously working remote into an unexplained auth failure** — `/Users/ryanliu/Documents/Terum/terum-codex/m1-plumbing/src/lib/remote.ts:133`
