# ultrareview: phase1-closeout

Verdict: this fix-scoped confirmation pass over `775e223`/`3a9088a` (diff `0e0c150...HEAD`) finds the commit closed its targets but introduced a cluster of regressions in the hardening itself. The most serious is a strict worsening: converting `config.teams[name]` to `Object.hasOwn` at the three `team.ts` gates without converting the sink they both feed (`src/lib/auth.ts:179`) moved a prototype-named team's rejection from *before* any network work to *after* `gh repo create` / after a durable roster push — the join path then loops forever. Four more medium regressions follow the same shape — a guard or a reuse swap applied at one point in a sequence but not at the point where the sequence actually decides: sync's lock hoisted above the no-op fast path (false "Blocked … busy" and inflated hook review counts on concurrent runs), search's `Promise.all` over `latestTree` making one unresolvable skill drop every hit for the team, setup's new missing-clone guard placed after share/invite/`offerHook` so the machine is mutated before the wizard declares failure, and `restoreDisplaced`'s single-condition early return orphaning `.terum-*.old` inside the skills root — the exact invariant its own comment cites. Test coverage for the new branches is thin: `mkdirPrivate`'s foreign-uid throw (on the config-write hot path) is untested, the new setup test picks the one branch where nothing else touches the clone, `canonicalDigest`'s changed wire format has only relative assertions, and the new prompt test cannot detect deletion of the pre-check it is named after. Nothing critical; nothing blocking a merge that a focused follow-up cannot clear, but findings 0–2 should land before this branch is treated as closed out.
