Repo root: `/Users/ryanliu/Documents/Terum/terum-codex/m1-plumbing` — all paths below are relative to it. Mode: working tree vs HEAD, verify=full (3-vote adversarial).

**Verdict.** 33 findings survived verification; one residual near-duplicate pair was merged here (the `team join` clone-collision reported at `commands/team.ts:64` and at `lib/teamRepo.ts:14` is one defect seen from the command and library sides), leaving **32 confirmed**. The M1 plumbing is structurally right — Prompter boundary, Result type, retry-with-deadline `safeWrite`, guard predicates — but it does not survive its own primary path: the CLI never exits because `terminalPrompter()` leaks a readline interface, and `team create <name>` without `--org` constructs `https://github.com/<name>.git`, an ownerless URL that 404s on push. Below that, four themes dominate the high band. (1) The write guard, the one control standing between a mutation and the shared team repo, is bypassable four ways: it reads ownership from the *post-image* of SKILL.md so a diff can grant itself authorship; it parses `author:` with a hand-rolled regex over the whole file instead of the existing `parseSkillFrontmatter`; `archivedRemovedOnly` checks only length so a join can silently re-admit or eject other members; and `git add --all` commits untracked files the guard never saw. (2) Identity bindings are not honoured — `login` clobbers the immutable per-team handle and any stored PAT, a repeat `join` mints a duplicate people file, and clone directories keyed on the repo *basename* let `orgB/skills` push your people file into `orgA/skills`. (3) The auth flow works only on the happy path: the creator PAT is threaded into `gh` but not into `git push`, `gh`-less machines get `spawn gh ENOENT` after the user pastes a secret, and the non-TTY gate is dead code because no production caller injects `isTTY`. (4) The eslint Prompter boundary — which CLAUDE.md designates as the mechanism a second agent must obey — is defeated by `import { stdout } from 'node:process'` (the exact idiom `prompt.ts` itself uses) or by dropping the `node:` prefix, and only 1 of its 3 rules is tested, so both bypasses shipped invisibly. Fix the two criticals and the guard cluster before anything else; the medium band is mostly test-coverage debt that would have caught these.

## Terum invariants

- [ ] **(critical) `terminalPrompter()` never closes its readline interface — the CLI hangs forever after every command** — `src/lib/prompt.ts:18` _(merges 9 reports across Terum invariants / Security / Correctness / Reuse — the single most independently rediscovered defect in the diff)_
  - Evidence: the interface is created per call and never closed, and the `Prompter` interface (lines 5-10) exposes no `close`/`dispose`, so no caller can close it either. `execute()` (`index.ts:22-26`) builds one per invocation and returns without exiting; there is no `process.exit()` anywhere and `await program.parseAsync()` is the last statement. An attached readline keeps stdin ref'd so the event loop never drains. Verified empirically: a child creating the same interface, answering one question and returning had not exited after 2s (`RESULT: STILL RUNNING after 2s`) despite the work completing. Effect: `team create foo` / `team join org/repo` print `Created team …` and then hang until Ctrl-C, which also replaces the intended exit code (0, or the 1 set on failure) with 130 — so any script, `npx` chain, or the phase-2 `setup` wizard stalls on the first verb.
  - Fix: add `close(): void` (or `[Symbol.asyncDispose]`) to `Prompter` returning `terminal.close()`, give `ScriptedPrompter` the same no-op member, and wrap `execute()`'s body in `try { … } finally { io.close(); }`. Fix it in `execute()`/`terminalPrompter` rather than per-command, since every future verb routes through it. Creating the interface lazily on first question would also stop non-interactive commands from ever touching stdin. Add a smoke test that runs `dist/index.js` to completion with a timeout.
