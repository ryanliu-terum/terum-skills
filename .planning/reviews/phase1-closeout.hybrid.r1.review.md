# ultrareview: phase1-closeout

**Verdict.** The close-out commit (0e0c150, diff `81bf9a6...HEAD`) does real hardening — a `busy` set that keeps one locked clone from killing a whole sync, an `Object.hasOwn` sweep over project lookups, per-candidate and per-placement error containment, a degraded setup summary, EPIPE tolerance, and a batch of new tests. Nothing here is a merge blocker. What it does ship is a set of **half-finished guards**: `refreshClone`'s new lost-lock error is not `CloneBusy`, so the very failure the `busy` set exists for still aborts the entire sync and fails the SessionStart hook; the `Object.hasOwn` sweep missed `selectTeam`, so `--team constructor` still resolves to `Object.prototype.constructor` on every verb the commit just routed through that resolver; and the new `member <handle>` guards reject an empty handle but not `../../../etc/passwd`, which still reaches `readPerson`'s `join()`. Alongside those, several of the new tests cannot fail — `installs: 0` on a roster with no installs, a `stdio: 'inherit'` probe that passes when piped, a clone-lock test that exercises 2 of the 5 new busy guards — and moving the `tsc` build into `beforeAll` silently cut its budget from the configured 120 s `testTimeout` to vitest's 10 s default `hookTimeout`. Fix the three half-guards and the timeout first; the rest are tightenings.
