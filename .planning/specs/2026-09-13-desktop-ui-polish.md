## E — Library multi-select and bulk "Publish to team" (LibraryScreen.tsx, LibrarySelectionBar.tsx, BulkPublishDialog.tsx, SkillCard.tsx/.css, Checkbox.tsx, publish-outcome.ts)

- Selection mode `?select=1` (Global and checkout scopes): a `Select`/`Done` ghost button in `SearchRow`'s `trailing` slot (accepted deviation: it narrows the search field on the Library boards; listed in FIDELITY.md once landed). - `.library-selection-bar` between the search row and the grid: `N of M selected` (M = cards currently drawn after query/facets) · Select all · Clear · primary `Publish N to team…`; `children` slot after Publish for a later "Evaluate N…" (the auto-update/auto-sync session's `?dialog=bulk-eval&ref=…` contract). Escape exits selection mode only when no filter popover or dialog is open and focus is not in a field. The selected set is component state keyed `path ?? name`; changing query/facets keeps it.
- `?select=1&dialog=publish` → `BulkPublishDialog` (shared Dialog, 440 px, rows scroll at 240 px): rows in draw order, `Ready` or `Skipped · <localActionReason(card,'publish')>`; confirm runs `backend.publish({ref: !card.teamed && card.path ? card.path : card.name, team?})` ONE AT A TIME through `driveRun` (the clone is write-locked), `Publishing… <progress label>` / `Queued`; each row then reads the single publish's outcome sentence via the new shared `publishOutcomeText(name, result)` (SkillScreen calls it too, so the two cannot drift) or `Failed · <CLI error>` (verbatim; the CLI accepts a folder path as the ref since #193); a cancelled run reads `Cancelled` and the rest `Not started`; any other failure continues with the next skill. Cancel cancels the active run and stops the queue; outside-press is refused while running; `TerminalHint` shows the first ready row's `npx -y terum-skills@latest publish <name>` (+ `… and N more`). Done invalidates `['library']` and `['skill']`, clears the selection, exits selection mode and sets a `role="status"` notice `Published X of N skills` (+ ` · Y failed`).
- Tests: bulk-publish.test.tsx (sequential order gated on a deferred promise, per-row outcomes, a failing row not stopping the queue, cancel mid-queue, empty dialog from a pasted URL, Escape precedence); library-skill.test.tsx's four outcome cases unchanged after the helper extraction; routes.spec extra `#/library/global?select=1`.

## F — scroll follow-ups (SkillScreen.tsx, EvaluationReport.tsx, skill.css, EvaluationReport.css, pane-focus.test.tsx)

- The panes had no focusable content (the report renders no button or link), so keyboard scrolling survived only through Chromium's keyboard-focusable-scroller heuristic and not on WKWebView (the macOS bundles). `.skill-md-blocks`, `.evals-main`, `.quality-tab`, `.activity-tab` carry `tabIndex={0} role="region" aria-label` (SKILL.md / Evaluation report / Quality / Activity); the History rail `aside` carries `tabIndex={0} aria-label="Run history"`. The app's accent ring (`outline:2px solid var(--tk-accent);outline-offset:-2px`, inside the box because the parent clips) on `:focus-visible` only — a mouse click focuses the pane without a ring.
- `.detail-body.full .skill-md-tab{overflow:visible}` (`?full=1&tab=skill` clipped at the tab while its blocks were visible); `.hygiene-row,.activity-row{flex-shrink:0}` (rows compressed instead of scrolling).
- Measured: 0 boxes and 0 pixels differing on the 19 SkillDetail boards + 2 tall probes at threshold 0. scroll.spec.ts: Tab from the tab strip reaches the pane within six presses (SKILL.md: the three other tabs, "Open in editor", the pane), PageDown scrolls it, the ring shows for keyboard focus and not for a click; the squeezed History rail scrolls with ArrowDown; full SKILL.md renders in one piece. The smallest-window case was corrected while running the suite for the first time: at 960 px the provenance line wraps to 208 px, taller than the floored pane's 160 px of content, so the assertion is that the pane shows its END (last line inside, above the 28 px clearance), not that a 208 px element fits whole.
